# xlerobot

Dual SO-100 + differential-drive base, teleoperated remotely over [XoQ](https://github.com/haixuanTao/wser).

Three Feetech buses on the robot (left arm, right arm, wheels) are each exposed
as one XoQ serial-server. From any operator machine, Python clients open those
remote ports through the same `serial.Serial(...)` API used for local serial —
the [`xoq_serial`](https://github.com/haixuanTao/wser) import hook routes
64-char iroh IDs over the network.

```
robot machine                          operator machine
─────────────                          ────────────────
/dev/tty.*-ARM-L  ──┐                  ┌── leader L  /dev/tty.*-LEADER-L
/dev/tty.*-ARM-R  ──┤  xoq_servers.py  │   leader R  /dev/tty.*-LEADER-R
/dev/tty.*-WHEELS ──┘    ↓                ↑
                       3 iroh IDs ──── xoq_config.json ──┐
                                                         ├─ wheel_client.py
                                                         └─ teleop_client.py
```

## Files

| Script | Side | What it does |
|--------|------|--------------|
| `xoq_servers.py` | robot | Builds & launches 3 `serial-server` processes (one per Feetech bus) with stable iroh identities; writes `xoq_config.json`. |
| `xoq_config.json` | both | Generated by `xoq_servers.py`. Maps `left-arm` / `right-arm` / `wheels` → iroh ID + port + baud. **Not committed** — copy it to the operator machine after first server boot. |
| `wheel_control.py` | local-only | Original local diff-drive keyboard teleop (real `/dev/tty...`). |
| `wheel_client.py` | operator | Same keyboard UI as `wheel_control.py`, but talks to the **wheels** XoQ server. |
| `teleop_client.py` | operator | Reads 1-2 local SO-100 leader arms with pyserial, mirrors poses to the remote followers via XoQ at 100 Hz. |

## Setup

You need [the `wser` repo](https://github.com/haixuanTao/wser) checked out and
its Python environment available on both machines (provides the `serial-server`
binary and the `xoq_serial` import hook).

```
# wser venv with xoq_serial installed
WSER_PY=/path/to/wser/.venv/bin/python
```

## Robot side — start the servers

```
$WSER_PY xoq_servers.py
```

By default it auto-detects which `/dev/tty.usbmodem*` is which: a port whose
servos respond to Feetech IDs **7 and 8** is the wheels bus, ports responding
to ID **1** are arms (lowest path → left). Override any slot by passing
`--left-arm-port`, `--right-arm-port`, or `--wheels-port`.

First run builds `serial-server --features "iroh serial"` (~30s). After all 3
buses log a `Server ID:` line, the script writes `xoq_config.json` next to
itself. iroh identities are persisted under `~/.xoq/xlerobot/<name>/` so the
3 IDs are stable across restarts — you only copy the config file once.

## Operator side — drive the wheels

```
scp robot:.../xlerobot/xoq_config.json ./
$WSER_PY wheel_client.py
# w/s = forward/reverse | a/d = turn | space = stop | [/] = step | q = quit
```

## Operator side — teleop the arms

Plug both leader SO-100 arms into the operator machine, then:

```
$WSER_PY teleop_client.py \
  --leader-left-port  /dev/tty.usbmodem-LEADER-L \
  --leader-right-port /dev/tty.usbmodem-LEADER-R
# add --side left or --side right to teleop one arm
# add --ids 1,2,3,4,5 if your build has no gripper
```

Safety sequence on startup: torque off everything → seed each follower's goal
to its leader's current pose → wait for Enter → torque on followers → loop.
Ctrl-C disables follower torque.

## Hardware notes

- 3 separate USB-Feetech adapters, one per bus. Sharing one bus across both
  arms + wheels is possible but caps teleop rate well below 100 Hz and creates
  a single failure domain — see `git log` for the prior discussion.
- All 3 buses run at 1 Mbps.
- Wheels: STS3215 IDs 7 (left) and 8 (right), continuous-rotation mode.
- Arms: SO-ARM100 default IDs 1-6 (5 joints + gripper).
